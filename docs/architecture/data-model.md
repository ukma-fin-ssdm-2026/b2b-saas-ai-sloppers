# Модель даних

Логічна ER-модель сервісу «Студентське ком'юніті та Івенти». Діаграма: [`uml/data-model.puml`](uml/data-model.puml).

Цільова СУБД — PostgreSQL. Усі первинні ключі — `uuid`. Усі часові мітки — `timestamptz` і зберігаються в UTC; перетворення в Europe/Kyiv відбувається лише під час відображення та експорту в календар (NFR-011). Технічні таблиці (міграції, сесії) у модель не входять.

## Покриття ключових функцій

| Ключова функція | Сутності |
|---|---|---|
| Реєстрація та автентифікація | `user` |
| Керування головами організацій | `organization_head`, `user` |
| Каталог організацій | `organization`, `tag`, `organization_tag` |
| Збір подій скрейпером | `source`, `event` |
| Модерація та публікація подій | `event`, `organization` |
| Каталог подій і експорт у календар | `event`, `organization` |
| Дошка оголошень | `advert`, `advert_response` |

Додатково модель покриває модерацію користувачів і контенту (`ban`, `complaint`, `banned_word`;) та рейтинги (`author_rating`, `organization_rating`;).

## Сутності

### Користувачі та доступ

**user** — зареєстрований студент. `role` приймає значення `USER` або `GLOBAL_ADMIN`: Global Admin не має власних атрибутів, тому окрема таблиця не потрібна. Роль голови не зберігається тут, бо вона локальна для організації (див. `organization_head`). `is_active = false`, доки email не підтверджено. Поля `verification_code_hash`, `code_expires_at`, `code_attempts` зберігають поточний код підтвердження: одночасно в користувача активний лише один код, новий перезаписує старий.

**ban** — блокування користувача (FR-054). `banned_by = null` означає автоматичне блокування (FR-060), `expires_at = null` — безстрокове. Розблокування фіксується полями `lifted_by` і `lifted_at`, рядок не видаляється. Користувач вважається заблокованим, якщо існує бан з `lifted_at IS NULL` і `expires_at` порожнім або в майбутньому.

### Організації

**organization** — студентська організація. `website_url`, `instagram_url`, `whatsapp_url` — публічні посилання для профілю (FR-016); вони не використовуються скрейпером. `auto_publish` вмикає автопублікацію спаршених подій, за замовчуванням `false` (FR-029). `archived_at` не порожнє — організація в архіві і разом із подіями не показується в каталогах (FR-015).

**tag**, **organization_tag** — теги організацій зі зв'язком багато-до-багатьох (FR-014, FR-019). Теги винесено в окрему таблицю, щоб мати єдиний словник без дублікатів на кшталт «дебати» / «Дебати».

**organization_head** — призначення користувача головою конкретної організації (ABAC, FR-006). Рядки не видаляються: зняття ролі заповнює `revoked_by` і `revoked_at`. Завдяки цьому таблиця водночас є журналом змін ролей (хто, кому, коли призначив чи зняв; FR-013). Активні голови — рядки з `revoked_at IS NULL`. Призначення Global Admin самого себе головою фіксується так само.

### Джерела та події

**source** — Instagram-акаунт, підключений головою для скрейпера (FR-021, FR-022). Сутність існує виключно для Scraper Worker: `enabled` дозволяє тимчасово вимкнути збір, а `last_run_at`, `last_run_status`, `last_error` показують голові результат останнього запуску (FR-028, NFR-007). Єдиний тип джерела — `INSTAGRAM`; поле `type` залишено як точку розширення. `source.url` може збігатися з `organization.instagram_url`, але це різні дані: перше визначає, що парсити, друге — що показувати в профілі. Токени доступу до соцмереж у БД не зберігаються (NFR-010).

**event** — подія організації, створена скрейпером або головою вручну (FR-037). `created_by = null` і заповнений `source_id` означає, що подію створив скрейпер; для ручних подій `source_id = null`. `external_post_id` — ідентифікатор поста в Instagram, `original_url` — посилання на оригінал (FR-027).

Статуси: `PENDING` (на модерації, невидима Гостям і User; FR-030), `PUBLISHED`, `REJECTED` (відхилена головою; FR-035), `UNPUBLISHED` (знята з публікації після публікації; FR-036). `is_verified = false` позначає автоопубліковану подію, яку голова ще не переглянув (FR-032). `reviewed_by` — голова, що останнім схвалив, відхилив чи зняв подію.

У дайджест потрапляють події зі статусом `PUBLISHED`, `starts_at` у майбутньому та організацією без `archived_at` (FR-038).

### Дошка оголошень

**advert** — оголошення про пошук команди (`TEAM`) чи компанії для дозвілля (`LEISURE`) (FR-043). `contact` обов'язковий (FR-044) і є персональними даними (див. нижче). `status`: `ACTIVE`, `CLOSED` (закрите вручну, за дедлайном або після заповнення `slots`; FR-050, FR-051), `DELETED`. Оголошення заблокованого автора приховуються за наявністю активного бану, окремого статусу для цього немає (FR-055).

**advert_response** — відгук на оголошення (FR-046). `status`: `PENDING`, `CONFIRMED` (автор підтвердив, відгукувач бачить контакт; FR-049), `REJECTED`, `WITHDRAWN` (відкликаний до підтвердження; FR-053).

### Модерація контенту

**complaint** — скарга на оголошення або відгук (FR-056). Замість поліморфного `target_id` використано два nullable зовнішні ключі `advert_id` і `response_id`, щоб цілісність гарантувала БД. `status`: `OPEN`, `RESOLVED` (контент видалено; FR-057), `DISMISSED`.

**banned_word** — список заборонених слів для автофільтра, веде Global Admin (FR-058).

### Рейтинги (Could)

**author_rating** — оцінка автора учасником закритого оголошення (FR-061). Середній рейтинг обчислюється запитом (FR-062).

**organization_rating** — оцінка організації користувачем, яку можна змінити (FR-063). Рейтинги зберігаються окремими записами, а не агрегованим полем, бо потрібно знати, хто вже оцінив (обмеження «один раз») і яку оцінку змінити.

## Обмеження цілісності

| Обмеження | Сутність | Вимога |
|---|---|---|
| `UNIQUE(email)` | `user` | FR-001 |
| `UNIQUE(source_id, external_post_id)` — повторний або паралельний запуск скрейпера не створює дублікатів | `event` | FR-025, NFR-005 |
| `UNIQUE(user_id, organization_id) WHERE revoked_at IS NULL` — частковий індекс, бо ту саму людину можна призначити повторно | `organization_head` | FR-008 – FR-010 |
| `UNIQUE(advert_id, user_id)` — один відгук на оголошення | `advert_response` | FR-046 |
| `CHECK` — заповнено рівно одне з `advert_id`, `response_id` | `complaint` | FR-056 |
| `UNIQUE(rater_id, advert_id)` | `author_rating` | FR-061 |
| `UNIQUE(user_id, organization_id)` | `organization_rating` | FR-063 |
| `CHECK(score BETWEEN 1 AND 5)` | `author_rating`, `organization_rating` | FR-061, FR-063 |
| `CHECK(slots > 0)` | `advert` | FR-043 |
| `ON DELETE SET NULL` для `event.source_id` — видалення джерела не видаляє події | `event` | FR-022 |

Інваріанти, які схемою не виражаються і забезпечуються транзакціями з блокуванням рядків (NFR-006):

- в активній організації завжди є щонайменше один активний голова (FR-011, FR-014);
- кількість відгуків зі статусом `CONFIRMED` не перевищує `advert.slots`; досягнення ліміту закриває оголошення (FR-050).

Виявлення дублікатів однієї події з різних джерел (FR-026) ґрунтується на нечіткому збігу назви, тому виконується логікою Scraper Worker, а не обмеженням БД.

## Персональні та чутливі дані

| Поле | Категорія | Хто має доступ |
|---|---|---|
| `user.email` | PII | сам користувач, Global Admin; голова — під час пошуку користувача для призначення |
| `user.first_name`, `user.last_name` | PII | автентифіковані користувачі (автор оголошення чи відгуку, голова в журналі ролей) |
| `user.password_hash` | секрет | лише сервіс автентифікації; не повертається в API і не пишеться в логи (NFR-008) |
| `user.verification_code_hash` | секрет | лише сервіс автентифікації |
| `advert.contact` | PII | автор і підтверджені відгукувачі; для решти не повертається в жодній відповіді, лозі чи помилці (FR-049, NFR-009) |
| `advert_response.message` | PII (довільний текст) | автор відгуку, автор оголошення, Global Admin при розгляді скарги |
| `ban.reason` | чутливе | Global Admin, заблокований користувач |
| `organization_head` (історія) | внутрішнє | голови цієї організації, Global Admin (FR-013) |
