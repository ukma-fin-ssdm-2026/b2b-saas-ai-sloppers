# Модель загроз (STRIDE)

Аналіз виконано над [діаграмою розгортання](uml/deployment.md) із використанням позначок персональних і чутливих даних з [моделі даних](data-model.md). Вимоги безпеки: NFR-008 (паролі), NFR-009 (приватність контакту), NFR-010 (транспорт і секрети).

## Активи

| Актив | Де зберігається | Чому важливий |
|-------|-----------------|---------------|
| Облікові дані й PII: `user.email`, ім'я, `password_hash`, `verification_code_hash` | PostgreSQL | Персональні дані та доступ до акаунтів |
| `advert.contact`, `advert_response.message` | PostgreSQL | Контакт автора відкривається лише після підтвердження відгуку (NFR-009) |
| Ролі й історія голів (`organization_head`), бани | PostgreSQL | Визначають, хто що може модерувати |
| Токени доступу до соцмереж, JWT-секрет | K8s Secret | Доступ до джерел скрейпера та підпис сесій (NFR-010) |
| Події й оголошення | PostgreSQL | Цілісність каталогу |
| Доступність API й каталогу | Backend | NFR-001…003 |

## Межі довіри

| ID | Межа | Що перетинає | Чутливі дані |
|----|------|--------------|--------------|
| TB1 | Інтернет ↔ Ingress / Frontend | HTTPS-запити браузера | Облікові дані, JWT, PII |
| TB2 | Frontend (nginx) ↔ Backend | `/api` усередині кластера | JWT, усі запити API |
| TB3 | Backend ↔ PostgreSQL | SQL (`postgres-rw`) | Усі PII, `advert.contact` |
| TB4 | Backend (Scraper) ↔ Instagram | HTTP-запити назовні | Токени джерел, недовірений вміст постів |
| TB5 | Primary ↔ standby БД | Streaming-реплікація | Повна копія даних |
| TB6 | GitHub (Actions, GHCR, гілка `deploy`) ↔ Minikube | Pull образів і маніфестів (ArgoCD, kubelet) | Код, образи, маніфести |

## Матриця STRIDE

Кожній межі та компоненту поставлено шість питань STRIDE. У клітинці ID ризику з реєстру нижче, «—» означає, що за нашим аналізом сценарію атаки немає або ризик покритий іншим рядком.

| Компонент / межа | S | T | R | I | D | E |
|------------------|---|---|---|---|---|---|
| TB1 Інтернет ↔ Ingress / Frontend | T-01 | — | — | — | T-07 | — |
| TB2 Frontend ↔ Backend (API, Auth) | T-01 | — | T-06 | — | T-07 | T-02 |
| TB3 Backend ↔ PostgreSQL | — | — | — | T-03 | — | — |
| TB4 Scraper ↔ Instagram | — | T-04 | — | — | — | — |
| TB5 Primary ↔ standby | — | — | — | — | див. розділ «Прийняті ризики» | — |
| TB6 CI/CD ↔ кластер | — | T-05 | — | — | — | — |

## Реєстр ризиків

| ID | Межа / компонент | STRIDE | Сценарій | Оцінка | Контрзахід |
|----|------------------|--------|----------|--------|------------|
| T-01 | TB1, Auth Module (логін, код підтвердження, JWT) | Spoofing | Зловмисник перебором підбирає код підтвердження email або паролі, чи використовує викрадений JWT від імені голови | Висока | Ліміт `code_attempts` і `code_expires_at`, rate limiting на логін, bcrypt/Argon2 (NFR-008), токен доступу ≤ 60 хв і HTTPS (NFR-010) |
| T-02 | TB2, Backend API (ABAC голови) | Elevation of privilege | User підставляє в запит чужий `organization_id` чи `eventId` і модерує чужу організацію або отримує права адміна | Висока | Перевірка ролі й належності до організації на сервері при кожному запиті (ADR-002), автотести доступу, жодних прав зі значень клієнта |
| T-03 | TB3, API оголошень і PostgreSQL | Information disclosure | `advert.contact` потрапляє у відповідь списку, лог чи повідомлення про помилку стороннього користувача | Висока | Окремий DTO без `contact` для всіх, крім автора й підтвердженого відгукувача; автотест на всіх ендпоінтах (NFR-009); контакт не пишеться в логи |
| T-04 | TB4, Scraper Worker ↔ Instagram | Tampering | Зловмисний або зламаний пост (скрипт у тексті) потрапляє в опис події й виконується в браузері відвідувача | Середня | Екранування й санітизація при виводі, ліміти довжини полів, події за замовчуванням «На модерації» (FR-030) |
| T-05 | TB6, CI/CD (Actions, GHCR, гілка `deploy`) | Tampering | Компрометація токена GitHub або бота дозволяє підмінити образ чи маніфест у гілці `deploy`, ArgoCD розгорне підроблене | Середня | Мінімальні права `GITHUB_TOKEN`, образи за digest, PR-ревʼю для `main`, пуш у `deploy` лише ботом, 2FA в акаунтах команди |
| T-06 | Модерація, бани, ролі голів | Repudiation | Голова заперечує, що зняв подію чи призначив або зняв голову, і довести це нічим | Середня | `organization_head` як журнал змін ролей (FR-013), `event.reviewed_by`, `ban.banned_by`, audit-лог із користувачем і часом |
| T-07 | Ingress / Backend `/api` (один под) | Denial of service | Масові запити на каталог, пошук чи логін перевантажують backend з `replicas: 1` | Середня | Rate limiting на Ingress, пагінація з верхньою межею, probes і швидкий рестарт; залишок свідомо прийнято (див. нижче) |

## Прийняті ризики

- **T-07, залишок.** Backend працює в одному поді: rate limiting зменшує ризик, але не прибирає його. Для демо на Minikube це прийнято.
- **TB5, одновузловий Minikube.** Обидва поди БД стоять на одному вузлі, тож репліка захищає від падіння пода, але не машини (R-004 у вимогах). Реплікація йде всередині кластера, окремого сценарію атаки на цій межі не виявлено. Бекапи поза обсягом семестру.
