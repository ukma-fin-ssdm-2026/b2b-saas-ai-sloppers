# ADR-001: Архітектурний стиль

- **Статус:** Accepted
- **Дата:** 2026-09-30
- **Учасники рішення:** Architecture (Artem Butyrin)

## Context

Обмеження контексту:
- стек: React + Spring Boot + PostgreSQL, деплой у Minikube;
- за [Project-Description](../../../Project-Description.md) цільове місце сервісу — **мікросервісна** екосистема SmartUkma (`account-server`, `ui-constructor`), але в семестрі AuthZ і UI робимо самі;
- NFR (p95 ≤ 500 мс, цілісність даних, приватність контактів) вимагають простої, контрольованої схеми даних і чітких меж API.

## Decision

Обираємо **гібридну позицію**:

1. **У семестрі (те, що будуємо):** стиль **клієнт–сервер** (трирівневий):  
   React-клієнт -> Community Events Service (Spring Boot, всередині — шари API / домен / дані).  

2. **Глобально (цільовий контекст):** наш бекенд проєктується як **один мікросервіс** домену «організації та події» в SmartUkma. Зовнішні сервіси AuthZ/UI залишаються окремими мікросервісами; інтеграція з ними — після фінальної здачі.

## Alternatives considered

| Альтернатива | Чому ні зараз |
|--------------|---------------|
| Чисті мікросервіси з першого дня (окремі сервіси orgs / events / board / scraper) | Надмірна складність для команди 4 і 10 тижнів |
| Лише багатошаровий моноліт без акценту на мікросервіс | Суперечить міні-ТЗ і майбутній інтеграції в SmartUkma; |
| Event-driven як основний стиль | Немає вимог до складної асинхронної оркестрації між багатьма доменами; скрейпер достатньо закрити cron + синхронним API всередині сервісу. |

## Consequences

**Плюси**
- Проста модель розробки й деплою (один сервіс + БД + клієнт).
- Чіткий REST-контракт клієнт↔сервер під NFR продуктивності й безпеки.
- Збережена «межа мікросервісу»: пізніше можна підмінити AuthZ/UI на SmartUkma без переписування домену подій/оголошень.

**Мінуси / ризики**
- У семестрі сервіс несе AuthZ і (через React) UI-відповідальність -> пізніше знадобиться рефакторинг інтеграції (свідомо прийнято в міні-ТЗ).
- Єдина БД = сильна узгодженість зараз, але не «database per service» у чистому мікросервісному сенсі до моменту виділення інших доменів.
