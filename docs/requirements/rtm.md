# Матриця простежуваності вимог (RTM)

Матриця пов'язує користувацькі історії, функціональні вимоги, NFR
і тест-кейси. Вона відповідає на два питання:

- **Прямий напрямок:** чи має кожна історія відповідні вимоги та тести?
- **Зворотний напрямок:** чи покрита кожна вимога хоча б однією історією й тестом?

## Джерела

| Артефакт               | Файл                                                             | ID        |
| ---------------------- | ---------------------------------------------------------------- | --------- |
| Користувацькі історії  | [user-stories.md](user-stories.md)                               | `US-###`  |
| Функціональні вимоги   | [requirements.md](requirements.md), розділ FR                    | `FR-###`  |
| Нефункціональні вимоги | [requirements.md](requirements.md), розділ NFR                   | `NFR-###` |
| Тест-кейси             | цей файл, розділ 4                                               | `TC-###`  |

Тест-кейси описані як наміри перевірки. Стовпець «Тести» в розділі 4 показує, яким
рядком [тест-плану](../validation/test-plan.md) закрито TC (`П-№`), стан і автотест, якщо він уже є:
✅ — автотест у `main`, 🟡 — функція є, тесту ще немає, ⏳ — функції ще немає в `main`.

**Знайдені розбіжності:**

1. **FR-016** (голова редагує профіль своєї організації) має пріоритет Must, але не
   покритий жодною історією. Потрібна окрема історія.
2. **FR-021 суперечить FR-067.** FR-021 (Must) дозволяє джерела типу Instagram
   **або WhatsApp**, тоді як FR-067 виносить «джерела, крім Instagram» у Won't цього
   семестру. US-007 успадкувала суперечність: у її критеріях теж «Instagram або
   WhatsApp». Потрібно або звузити FR-021 і US-007 до Instagram, або переформулювати
   FR-067.
3. **FR-037** (створення події вручну) — Should, теж без історії. Це запасний шлях,
   якщо парсер не спрацює, тож історія бажана.
4. **FR-015** (архівування організації) згадується в критеріях US-002 і US-004
   («архівовані не показуються»), але саму дію ніхто не виконує в жодній історії.
5. **FR-012** (Global Admin замінює останнього голову одним запитом) — Should, історії
   немає. За змістом належить до US-006, але та описує лише дії голови, не адміна.
6. **FR-058 – FR-060** (автофільтр, обмеження частоти, автоблокування) за змістом є
   продовженням US-014, але в її критеріях не згадані.
7. **FR-061 – FR-064** (рейтинги) — Could, історій немає. Якщо залишаємо в обсязі,
   потрібна історія; якщо ні, переносимо в розділ Won't.

| NFR-008 | Security               | US-001                 | TC-046                 |
| NFR-009 | Security               | US-011, US-012, US-013 | TC-030, TC-033, TC-036 |
| NFR-010 | Security               | US-001, US-007         | TC-047                 |
| NFR-011 | Compatibility          | US-003                 | TC-008, TC-009         |
| NFR-012 | Compatibility          | наскрізна              | TC-042                 |
| NFR-013 | Functional suitability | US-008, US-009, US-010 | TC-020                 |

**Знайдені розбіжності:**

1. **US-014 (блокування порушника) не має жодної NFR.** Модерація напряму пов'язана
   з безпекою: варто додати вимогу про обмеження частоти дій (FR-059) або про час
   реакції на скаргу.
2. **NFR-005 посилається на FR-025 і FR-026, а NFR-007 — на FR-023 і FR-028.**
   FR-028 при цьому не покритий жодною історією, тобто нефункціональна
   вимога спирається на функцію, якої ніхто не замовляв.
3. **Категорій ISO 25010 п'ять** (Performance efficiency, Reliability, Security,
   Compatibility, Functional suitability) — вимогу лабораторної про мінімум три
   виконано.
