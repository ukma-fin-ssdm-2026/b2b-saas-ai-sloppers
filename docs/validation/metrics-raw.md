## Що вважається одним запуском

Розгортання в цій лабораторній — це наближення безперервної доставки: успішний запуск CI на `main`, а не викладка в робоче середовище.

Враховано один workflow — **CI**, jobs `Build and Test Backend` і `Build and Test Frontend`. Кожен коміт на `main` — один рядок, навіть якщо поряд ідуть інші workflow.

Поза підрахунком:

- **Lint** — звітний, збірку не валить, але займає self-hosted раннер.
- **SonarQube Cloud** — навмисно окремо від обов'язкових перевірок.
- **API Docs** і **Deploy API Docs to GitHub Pages** — документація, не зібраний застосунок.
- **Build and Deploy** — ручний `workflow_dispatch` (збірка образів і коміт у гілку `deploy` для ArgoCD). За вікно він запускався один раз, 01.11 о 23:43 (UTC+2), для коміту `ba81c05`. У таблицю нижче він не входить: визначення розгортання тут — зелений CI.

У цьому вікні Lint, API Docs і Sonar на `main` теж не мають червоних завершень. Скасовані рядки нижче збігаються зі скасуванням CI через `concurrency`.

## Як пораховано час

- **Черга** — від `created_at` запуску до `started_at` першого job.
- **Виконання** — від `started_at` першого job до `completed_at` останнього job. Сюди входить простій між job-ами, якщо раннер між ними віддали іншому workflow.
- **Перший коміт PR** — `authoredDate` найраннішого коміту pull request (не час squash-злиття).
- Час у таблиці — **UTC+2**.

Статуси: зелений запуск, червоний запуск (таких немає), скасований запуск. Скасування дає `concurrency.cancel-in-progress: true` на групі `ci-${{ github.ref }}`: новий пуш у `main` обриває попередній запуск. Це не червона збірка і не розгортання.
