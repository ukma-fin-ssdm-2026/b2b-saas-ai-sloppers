# Документація проєктування API

Мікросервіс «Студентське ком'юніті та Івенти» (частина екосистеми SmartUKMA), ресурс організацій.

## Огляд архітектури

- **Базова адреса:** `http://localhost:8080/api/v1`
- **Стиль API:** REST, ресурсно-орієнтований
- **Реалізація:** Java 21, Spring Boot 3, springdoc-openapi (Code-First), Bean Validation
- **Автентифікація:** JWT Bearer-токени власного AuthZ-сервісу (заплановано; у поточних заглушках не перевіряється, але 401/403 уже є частиною контракту)
- **Формат даних:** JSON, `application/json`, UTF-8; поля в camelCase
- **Дати й час:** ISO 8601 зі зсувом часового поясу (`2026-09-01T10:00:00+03:00`)
- **Ідентифікатори:** UUID
- **Стратегія версіонування:** версія в шляху URL (`/api/v1`, `/api/v2`)

## Модель ресурсів

### Ресурс Organizations

- **Кінцева точка:** `/organizations`
- **Опис:** каталог студентських організацій НаУКМА
- **Атрибути:**
    * `id` (uuid): унікальний ідентифікатор
    * `name` (string, 3–100): назва
    * `slug` (string, 3–50, `a-z0-9-`): унікальний людиночитаний ідентифікатор для URL фронтенду
    * `description` (string, ≤ 2000): опис діяльності
    * `instagramHandle` (string, без `@`): акаунт, з якого скрейпер збирає події
    * `contactEmail` (email): контакт організації
    * `createdAt`, `updatedAt` (date-time): службові мітки часу
- **Зв'язки:**
    * має багато подій (events)
    * має одного або кількох голів (heads)

### Кінцеві точки

| Метод | Шлях | Хто може | Успіх | Помилки |
|---|---|---|---|---|
| GET | `/organizations` | усі, зокрема гості | 200 | 400 |
| GET | `/organizations/{organizationId}` | усі | 200 | 400, 404 |
| POST | `/organizations` | суперадмін | 201 + `Location` | 400, 401, 403, 409 |
| PATCH | `/organizations/{organizationId}` | суперадмін, голова організації | 200 | 400, 401, 403, 404, 409 |
| DELETE | `/organizations/{organizationId}` | суперадмін | 204 | 400, 401, 403, 404 |

`400` на кінцевих точках з `{organizationId}` виникає, якщо ідентифікатор не є UUID.



### Обробка помилок

Усі помилки — і доменні, і помилки фреймворку (зламаний JSON, параметр не того типу, невідомий маршрут) — повертаються в одному каркасі:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Запит містить невалідні поля",
    "details": [
      { "field": "slug", "message": "Slug: лише a-z, 0-9 і дефіс між словами", "providedValue": "Debate Club!" }
    ],
    "requestId": "req_7f3a9c21d04b4e18",
    "documentation": "https://ukma-fin-ssdm-2026.github.io/YOUR-REPO/api/errors#validation-error"
  }
}
```

- `code` — машиночитаний, клієнт розгалужується саме за ним; `message` — для людини.
- `details` — по одному запису на кожне порушене поле або параметр; порожній масив, якщо не застосовно.
- `requestId` — ідентифікатор запиту для пошуку в логах.
- Назви класів винятків, стектрейси й SQL назовні не потрапляють; `500` повертає лише загальне повідомлення і `requestId`.
- У специфікації помилки описані як спільні компоненти `components/responses` (`BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`) з прикладами, і кожна кінцева точка посилається на потрібні.

| Код | HTTP | Коли |
|---|---|---|
| `VALIDATION_ERROR` | 400 | порушено правила валідації тіла або параметрів |
| `INVALID_PARAMETER` | 400 | параметр не того типу (напр. не UUID) або відсутній |
| `MALFORMED_REQUEST` | 400 | тіло відсутнє або не є коректним JSON |
| `UNAUTHORIZED` | 401 | немає або недійсний JWT |
| `FORBIDDEN` | 403 | роль не дозволяє дію |
| `ORGANIZATION_NOT_FOUND` | 404 | організації з таким `id` немає |
| `ROUTE_NOT_FOUND` | 404 | такої кінцевої точки немає |
| `METHOD_NOT_ALLOWED` | 405 | метод не підтримується ресурсом |
| `SLUG_ALREADY_EXISTS` | 409 | slug організації зайнятий |
| `INTERNAL_ERROR` | 500 | непередбачена помилка сервера |

### Версіонування

- Мажорна версія — у шляху: `/api/v1` (константа `ApiPaths.V1`).
- **Сумісні зміни** лишаються в `v1`: нові кінцеві точки, нові необов'язкові поля запиту, нові поля відповіді, нові коди помилок. Клієнти мають ігнорувати невідомі поля.
- **Несумісні зміни** — лише в `v2`: видалення чи перейменування поля, зміна типу, нове обов'язкове поле, зміна семантики статус-коду.

### Безпека

- Ролі: гість (без токена), студент, голова організації, суперадмін. Суперадмін керує організаціями й головами; щоб діяти в організації як голова, він має призначити головою себе.
- Читання каталогу — публічне. Операції запису позначені в специфікації `security: bearerAuth` і документують `401`/`403`.
- Усі вхідні дані валідуються на межі API; розмір сторінки обмежено зверху.
