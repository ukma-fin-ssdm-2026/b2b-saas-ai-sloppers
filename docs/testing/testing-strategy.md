# Стратегія тестування

Стратег: Артем Бутирін. Деталі прогону тестів і звіт покриття — у [README.md](README.md).

> Цифри й статус рівнів оновлено 31.10.2026 (Максим Костинюк, роль аналітика якості) за прогоном `./mvnw clean verify` і `npm run test:coverage`. Структура документа й рішення щодо рівнів — авторські.

## Поточний статус

Станом на 31.10.2026 піраміда вже не плоска: з'явився інтеграційний рівень і модульні тести фронтенду.

| Рівень (V-модель) | Зараз | Інструменти |
| ----------------- | ----- | ----------- |
| Модульний (бекенд) | Є: `organization`, `event`, `auth`, `storage`, `common` — 15 класів, 112 тестів | JUnit 5, Mockito, AssertJ, фікстури `TestFixtures` |
| Модульний (фронтенд) | Є: `api/organizations`, `pages/OrganizationsPage` — 14 тестів | Vitest, @testing-library/react, jsdom |
| Інтеграційний | Є: `AuthFlowIntegrationTest` — 3 сценарії через HTTP | `@SpringBootTest` + MockMvc, профіль `inmemory` |
| Системний | Немає | наскрізний гість → каталог orgs → події |
| Приймальний | Немає | демо за US з Lab 2 |

Усього в бекенді **115** тестів (96 методів, частина параметризовані) і **14** у фронтенді.

Запуск: `./mvnw test` для бекенду, `npm run test` у `web-src/` для фронтенду. Тести бекенду в `src/test/java/` (стандарт Maven), фронтенду — поруч із кодом, що вони перевіряють.

**Чим інтеграційний рівень відрізняється від модульного тут.** `AuthFlowIntegrationTest` піднімає застосунок цілком і йде через справжній HTTP-стек: фільтри Spring Security, розбір JWT, маршрутизація, серіалізація. Моком лишається тільки `CodeSender` — щоб дістати код підтвердження замість надсилання листа. Саме тому цей тест ловить те, чого модульний не бачить: правило доступу в `SecurityConfig` живе не в сервісі, і перевірити його можна лише запитом.

Проміжний випадок — `SupabaseImageStorageTest`: він не піднімає застосунок, але й не мокає `RestClient`, а підставляє `MockRestServiceServer`, тобто фальшивий HTTP-сервер. Перевіряється справжня побудова запиту (метод, шлях, заголовки, тіло), і при цьому тест залишається швидким і не залежить від мережі.

## Покриття

Знімок JaCoCo: [`coverage/jacoco/`](coverage/jacoco/index.html) (колонки LINE у `jacoco.csv`).

- **Рядки: 62.1%** (808 / 1302), інструкції 66.8%, гілки 59.5%. Ворота в `pom.xml` (`jacoco-check`) досі **5%** рядків — і це вже не відповідає факту (див. «Відкриті дії»).
- По пакетах: `storage` 88.9%, `organization` 68.8%, `auth` 62.9%, `common/error` 62.7%, `event` 55.4%, `calendar` 12.5%.
- **Зовсім не покрито** (0 рядків): три JDBC-репозиторії — `JdbcHeadRepository` (87 рядків), `JdbcEventRepository` (57), `JdbcOrganizationRepository` (48) — а також `MailCodeSender`, `LogCodeSender` і `GoogleCalendarLink`.
- **`calendar` — 12.5%** і найслабше місце звіту: експорт `.ics` (RFC 5545) має власне кодування рядків і згортання довгих, тобто це готовий до тестування чистий код без залежностей, який просто ніхто не покрив.

**Про JDBC-репозиторії окремо.** 192 непокриті рядки — це не недогляд, а межа підходу: модульні тести ганяються на in-memory реалізаціях, а SQL виконується лише проти справжнього PostgreSQL. Доки немає Testcontainers, покриття цих класів у звіті буде нуль, і жодна правка тестів цього не змінить. Тому 62.1% — це покриття домену, а не всього коду: без JDBC-шару воно було б 75.7% (808 / 1068).

## План наступних рівнів

1. **Інтеграційні — розширити.** MockMvc уже працює (`AuthFlowIntegrationTest`), але покриває лише `auth` і `organizations`. Бракує того самого для подій (створення, модерація, дайджест) і для завантаження картинок. Наступний крок після цього — Testcontainers PostgreSQL замість профілю `inmemory`: сервіс уже має JDBC-реалізації й міграції Flyway, тож тестувати є що, і 192 непокриті рядки SQL закриваються лише так.
2. **Системні (система як чорна скриня):** один сценарій: відкрити UI → список організацій з живого API (proxy `/api`). Без повного E2E-фреймворку; тепер, коли Auth стабілізувався, обмеження зняте — бракує часу, а не передумов.
3. **Приймальні (вимоги):** чекліст демо за US/FR Lab 2 (каталог, модерація, дедуп) на лабораторній, не в CI.

Пропорція-ціль піраміди: багато модульних на кожен PR; мало інтеграційних на merge; одиниці системних перед демо.

## Продуктивність, безпека, property-based

- **Продуктивність:** окремих тестів немає; NFR з Lab 2 перевірятимемо після деплою в Minikube, не в модульному наборі.
- **Безпека:** не дублюємо SAST тут — SpotBugs + find-sec-bugs і eslint-plugin-security уже в Lab 5 (`lint.yml`). Динамічні тести доступу з'явилися: `AuthFlowIntegrationTest` перевіряє `401` без токена, `403` для чужої ролі й `WWW-Authenticate: Bearer` у відповіді. Це поки що єдиний рівень, де правила доступу взагалі перевіряються, бо правило `SPRING_ENDPOINT` у SpotBugs придушене — див. [static-analysis.md](../code-quality/static-analysis.md).
- **Property-based:** не використовуємо (jqwik / fast-check — кандидат на бонус, не на цей спринт).

## CI/CD (shift-left)

На кожен push/PR у `main` job **Build and Test Backend** у [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml):

1. компіляція тестів;
2. `./mvnw test` — Surefire + звіт JaCoCo + **падає, якщо покриття рядків < 5%**;
3. package;
4. summary (кількість тестів, % рядків) і артефакт `test-reports` (7 днів).

Job **Build Frontend** у тому ж workflow виконує `npm ci` → `npm run test` (Vitest) → `npm run build` (`tsc -b` + Vite). Merge в `main` лише з зеленим CI і approve (§5 статуту). Локально автор ганяє `./mvnw test` і `npm run test` перед PR.

## Відкриті дії

1. **Підняти поріг `jacoco-check`.** 5% при фактичних 62.1% — ворота, які вже нічого не ловлять: можна видалити три чверті тестів і збірка залишиться зеленою. Умова «коли покриття стабілізується вище ~40%» із попередньої редакції виконана. Розумний поріг — 55–60% рядків: нижче факту настільку, щоб нова непокрита фіча не валила PR, але достатньо високо, щоб зникнення набору тестів було видно.
2. **Інтеграційні тести на події й картинки** — за зразком `AuthFlowIntegrationTest`.
3. **Testcontainers PostgreSQL** — єдиний спосіб покрити 192 рядки JDBC-репозиторіїв.
4. **Тести `calendar`** — 12.5% на чистому коді без залежностей; найдешевший приріст покриття з усіх можливих.
