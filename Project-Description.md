# Project Description — Мікросервіс «Студентське ком'юніті та Івенти»

## Опис ідеї проєкту

Бекенд-мікросервіс для централізованого управління студентськими організаціями, автоматичної агрегації їхніх подій та P2P-взаємодії студентів (пошук команд, компанії для дозвілля). Головна проблема, яку розв'язує система, - операційне навантаження на лідерів організацій: замість ручного дублювання анонсів у різних каналах сервіс самостійно стягує інформацію з підключених соцмереж організації, розпізнає з неструктурованого тексту події (назва, час, локація) і після модерації публікує їх у єдиному каталозі.

Передбачається, що сервіс не буде самостійним застосунком, а безшовно вбудовується в наявну мікросервісну архітектуру Смарту: автентифікація та глобальні ролі гарантуються існуючим account-server, а клієнтська частина рендериться через ui-server-ui-constructor - сервіс лише віддає JSON, який мапиться на готові візуальні блоки.

Але в межах проєкту – для більшого наповнення та використання більшої кількості технологій – плануємо реалізувати свої AuthZ, UI/UX та розгортання через Minikube, а вже після завершення проєкту відбудеться повноцінна інтеграція в існуючу мікросервісгу архітектуру SmartUkma.

## Ролі користувачів

- Global Admin - глобальна роль (з account-server), заводить нові організації та призначає їм першого координатора.
- Coordinator - локальна роль (ABAC) у межах однієї організації; керує профілем, джерелами та модерацією подій своєї організації.
- User (Студент) - базова автентифікована роль; переглядає дайджести, експортує події в календарі, працює з дошкою пропозицій.

## Список функцій

1. Каталог організацій з логотипами, тегами, повнотекстовим пошуком і пагінацією.
2. Профіль організації.
3. Автоматичний парсинг подій із соцмереж (Scraper Worker) із дедуплікацією.
4. Модерація спаршених подій координатором.
5. Експорт подій у календар.
6. Дошка пропозицій з відгуками, підтвердженням і авто-закриттям.

# Міні-ТЗ

## Призначення системи

Система розв'язує проблему ручного дублювання анонсів студентськими організаціями та фрагментованості інформації про студентські події. Для лідерів організацій вона автоматизує збір та публікацію подій із їхніх соцмереж, для студентів надає єдиний каталог організацій і подій з експортом у календарі та дошку для пошуку команд/компанії.

## Межі системи

У обсязі цього семестру:

- CRUD організацій та їхніх профілів; каталог із пошуком і пагінацією.
- Scraper Worker (Cron) із витягуванням полей  і дедуплікацією.
- Модерація подій координатором.
- Генерація Google Calendar deep link та .ics
- Дошка пропозицій і відгуків.
- Реєстрація та логін користувачів/
- Розгортання через Minikube

Свідомо поза обсягом:

- Додати OAuth.
- Делегування AuthZ та фронтенд / рендеринг UI окремим мікросервісам в SmartUkma (account-server, ui-server/constructor).
- Зберігання розширених профілів делегується теж account-server; фронтенд підтягує їх сам.
- Мобільний застосунок.

## Нефункціональні вимоги

1. Продуктивність.
2. Надійність / цілісність даних.
3. Безпека / приватність (обов'язкова). Контактні дані не повертаються в жодній відповіді API нікому, окрім автора пропозиції.
4. Коректність часу / сумісність.

## Припущення та обмеження

- Стек: Java 21, Spring Boot, PostgreSQL для бекенду, React - фронтенд.
- Зовнішні сервіси: account-server (в майбутньому) (автентифікація, глобальні ролі, валідація користувачів), ui-server/constructor (рендеринг), джерела соцмереж, Google Calendar.
- Обмеження скрейпера:  RegEx/легкий NLP допускають помилки розпізнавання, тому всі спаршені події проходять ручну модерацію координатором (карантин).
- Обмеження команди: 4 студенти, до 10 тижнів.
