# Project Description — Мікросервіс «Студентське ком'юніті та Івенти»

## Опис ідеї проєкту

Бекенд-мікросервіс для централізованого управління студентськими організаціями, автоматичної агрегації їхніх подій та P2P-взаємодії студентів (пошук команд, компанії для дозвілля). Головна проблема, яку розв'язує система, - операційне навантаження на лідерів організацій: замість ручного дублювання анонсів у різних каналах сервіс самостійно стягує інформацію з підключених соцмереж організації, розпізнає з неструктурованого тексту події (назва, дата, час) і публікує їх у єдиному каталозі — після модерації головою або одразу, якщо організація ввімкнула автопублікацію.

Передбачається, що сервіс не буде самостійним застосунком, а безшовно вбудовується в наявну мікросервісну архітектуру Смарту: автентифікація та глобальні ролі гарантуються існуючим account-server, а клієнтська частина рендериться через ui-server-ui-constructor - сервіс лише віддає JSON, який мапиться на готові візуальні блоки.

Але в межах проєкту – для більшого наповнення та використання більшої кількості технологій – реалізуємо власні AuthZ, UI/UX та розгортання через Minikube, а вже після завершення проєкту відбудеться повноцінна інтеграція в існуючу мікросервісну архітектуру SmartUkma ([ADR-002](docs/architecture/decisions/ADR-002-auth-and-ui-in-semester.md)).

## Ролі користувачів

Назви ролей збігаються з [requirements.md](docs/requirements/requirements.md).

- **Гість** - неавтентифікований відвідувач; переглядає каталог організацій і опубліковані події.
- **User (студент)** - зареєстрований користувач з підтвердженою поштою @ukma.edu.ua; експортує події в календар, працює з дошкою пропозицій.
- **Голова організації** - локальна роль (ABAC) у межах однієї організації; керує профілем, джерелами, подіями та модерацією своєї організації, призначає й знімає інших голів.
- **Global Admin** - суперадмін. У цьому семестрі — власна роль сервісу (після інтеграції її надаватиме account-server). Створює й архівує організації та призначає голів; прав голови автоматично не має, тож для дій усередині організації призначає головою себе.

## Список функцій

1. Каталог організацій з логотипами, тегами, повнотекстовим пошуком і пагінацією.
2. Профіль організації.
3. Автоматичний парсинг подій з Instagram (Scraper Worker) із дедуплікацією.
4. Модерація спаршених подій головою організації або автопублікація.
5. Експорт подій у календар.
6. Дошка пропозицій з відгуками, підтвердженням і авто-закриттям.

# Міні-ТЗ

## Призначення системи

Система розв'язує проблему ручного дублювання анонсів студентськими організаціями та фрагментованості інформації про студентські події. Для лідерів організацій вона автоматизує збір та публікацію подій із їхніх соцмереж, для студентів надає єдиний каталог організацій і подій з експортом у календарі та дошку для пошуку команд/компанії.

## Межі системи

У обсязі цього семестру:

- CRUD організацій та їхніх профілів; каталог із пошуком і пагінацією.
- Scraper Worker (Cron) для Instagram із витягуванням полів і дедуплікацією.
- Модерація подій головою організації; автопублікація за вибором організації.
- Генерація Google Calendar deep link та .ics.
- Дошка пропозицій і відгуків.
- Реєстрація з підтвердженням пошти, логін і рольова модель.
- Розгортання через Minikube.

Свідомо поза обсягом:

- OAuth.
- Джерела, крім Instagram (зокрема WhatsApp).
- Делегування AuthZ та фронтенд / рендеринг UI окремим мікросервісам в SmartUkma (account-server, ui-server/constructor).
- Зберігання розширених профілів делегується теж account-server; фронтенд підтягує їх сам.
- Мобільний застосунок.

## Нефункціональні вимоги

Вимірювані значення й способи перевірки — у розділі NFR [requirements.md](docs/requirements/requirements.md).

1. Продуктивність.
2. Надійність / цілісність даних.
3. Безпека / приватність (обов'язкова). Контактні дані не повертаються в жодній відповіді API нікому, окрім автора пропозиції.
4. Коректність часу / сумісність.

## Припущення та обмеження

- Стек: Java 21, Spring Boot, PostgreSQL для бекенду, React - фронтенд.
- Зовнішні сервіси: account-server (в майбутньому) (автентифікація, глобальні ролі, валідація користувачів), ui-server/constructor (рендеринг), Instagram, Google Calendar.
- Обмеження скрейпера: RegEx/легкий NLP допускають помилки розпізнавання, тому за замовчуванням спаршені події потрапляють на модерацію голови. Організація може ввімкнути автопублікацію — тоді подія публікується одразу з позначкою «неперевірена», а голова виправляє її після публікації (FR-029 – FR-032).
- Обмеження команди: 4 студенти, до 10 тижнів.

## Критерії приймання

Систему вважаємо прийнятою наприкінці семестру, якщо виконуються всі пункти:

1. **Реєстрація.** Акаунт створюється лише для пошти @ukma.edu.ua і активується кодом із листа; неактивний акаунт не може увійти.
2. **Ролі.** Global Admin створює організацію одразу з першим головою; голова призначає й знімає голів своєї організації; спроба змінити чужу організацію повертає 403.
3. **Каталог.** Гість без входу бачить каталог організацій із пошуком і пагінацією, профіль організації та опубліковані майбутні події.
4. **Події.** Голова створює, редагує, схвалює, відхиляє й знімає з публікації події своєї організації; подія «На модерації» невидима Гостю та User.
5. **Скрейпер.** Після підключення Instagram-джерела новий пост з анонсом стає подією з назвою, датою, часом і посиланням на пост; повторна обробка того самого поста не створює дубліката.
6. **Календар.** Для опублікованої події генеруються Google Calendar deep link і `.ics`, що імпортується в Google Calendar із правильним часом (Europe/Kyiv).
7. **Дошка.** Оголошення без контакту автора відхиляється; контакт бачить лише відгукувач, якого автор підтвердив.
8. **Запуск.** Система піднімається локально однією командою (`docker compose up --build`) і в Minikube (`infra/helpers/up.sh`); CI на `main` зелений.
